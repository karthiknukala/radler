Docker Support for Radler
=========================

Radler provides Docker support for both building and deploying ROS2 applications.
This enables platform-independent development and deployment of Radler-generated systems.

Overview
--------

There are two Docker images:

1. **radler/builder** - A build environment containing Radler + ROS2 + colcon.
   Use this to compile your ``.radl`` files into ROS packages.

2. **Per-node containers** - Generated by Radler when you use the ``--docker`` flag.
   These are minimal runtime containers for each node in your plant.

Quick Start
-----------

Building the Builder Image
~~~~~~~~~~~~~~~~~~~~~~~~~~

First, build the Radler builder image::

    cd /path/to/radler/docker/builder
    docker build -t radler/builder .

Option A: Generate ROS Packages Only
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Mount your project and generate ROS packages::

    docker run -v $(pwd)/my_project:/project \
               -v /tmp/ros_ws:/output \
               radler/builder \
               /project/my_system.radl --plant plant

This generates ROS packages in ``/tmp/ros_ws/src/``. You can then build them
on any ROS2 system::

    cd /tmp/ros_ws
    source /opt/ros/jazzy/setup.bash
    colcon build

Option B: Generate ROS Packages + Build
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Add ``--build`` to also compile the packages::

    docker run -v $(pwd)/my_project:/project \
               -v /tmp/ros_ws:/output \
               radler/builder \
               /project/my_system.radl --plant plant --build

Option C: Generate Docker Containers
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Add ``--docker`` to generate per-node Dockerfiles and docker-compose.yml::

    docker run -v $(pwd)/my_project:/project \
               -v /tmp/ros_ws:/output \
               radler/builder \
               /project/my_system.radl --plant plant --docker --build

This generates:
- ROS packages in ``/output/src/<package>/``
- Built executables in ``/output/install/``
- ``Dockerfile.<node>`` for each node in ``/output/src/<package>/docker/``
- ``docker-compose.yml`` to orchestrate all nodes

You can then build and run all containers::

    cd /tmp/ros_ws/src/<package>/docker
    docker-compose build
    docker-compose up

Using the ``--docker`` Flag with Radler Directly
------------------------------------------------

If you have Radler installed locally, you can use the ``--docker`` flag directly::

    ./radler.sh --ws_dir /tmp/ros_ws/src compile my_system.radl --plant plant --ROS --docker

Additional options:
- ``--ros_distro <distro>`` - ROS distribution (default: jazzy)
- ``--ros_domain_id <id>`` - ROS domain ID for network isolation (default: 0)

Example: Pubsub Multi-Machine
-----------------------------

For the pubsub example::

    # Generate with Docker support
    docker run -v /path/to/radler/examples:/examples \
               -v /tmp/ros_ws:/output \
               radler/builder \
               /examples/pubsub/multi_machine/pubsub.radl --plant plant --docker --build

    # Build the containers
    cd /tmp/ros_ws/src/pubsub/docker
    docker-compose build

    # Run all nodes
    docker-compose up

    # Or run individually in separate terminals
    docker-compose up talker
    docker-compose up listener

SROS2 Security (Optional)
-------------------------

For secure ROS2 communication, add ``--sros2`` when building::

    docker run -v $(pwd)/my_project:/project \
               -v /tmp/ros_ws:/output \
               radler/builder \
               /project/my_system.radl --plant plant --docker --build --sros2

This will generate SROS2 keystores in ``/output/sros2_keys/``.

To run nodes with security enabled::

    export ROS_SECURITY_KEYSTORE=/path/to/sros2_keys
    export ROS_SECURITY_ENABLE=true
    export ROS_SECURITY_STRATEGY=Enforce
    ros2 run pubsub talker --ros-args --enclave /talker_listener/talker

Directory Structure
-------------------

::

    docker/
    ├── builder/
    │   ├── Dockerfile          # Build environment image
    │   └── radler-build.sh     # Build script / entrypoint
    ├── runtime/
    │   ├── Dockerfile.template      # Template for per-node Dockerfiles
    │   └── docker-compose.template.yml
    ├── README.rst              # This file
    └── sros_env.list           # Environment variables for SROS2

Mapping Radler Concepts to Docker
---------------------------------

The ``--docker`` flag maps Radler's plant structure to Docker:

- Each **node** becomes a container (via ``Dockerfile.<node>``)
- The **plant** becomes a ``docker-compose.yml``
- **linux** blocks with IPs can inform network configuration

For example, this ``.radl``::

    talker : node { ... }
    listener : node { ... }
    
    sys2 : linux {
      IP 172.17.0.2
      NODES talker
    }
    
    sys3 : linux {
      IP 172.17.0.3
      NODES listener
    }
    
    plant : plant {
      MACHINES
        host_computer {
          OS { VMS vm2 { OS sys2 } vm3 { OS sys3 } }
        }
    }

Generates:
- ``Dockerfile.talker``
- ``Dockerfile.listener``
- ``docker-compose.yml`` with both services

Troubleshooting
---------------

**Container can't communicate with other nodes:**
By default, containers use ``network_mode: host``. Ensure:
- All containers use the same ``ROS_DOMAIN_ID``
- Firewall allows multicast traffic
- For cross-host communication, ensure proper ROS2 DDS discovery configuration

**Build fails with missing dependencies:**
Ensure you're using a compatible base image. The default is ``ros:jazzy-ros-core``.

**Permission denied on mounted volumes:**
The build runs as root inside the container. Ensure the mounted directories
are writable, or use appropriate volume permissions.
